# Implementation Plan: Fused Diarization

**Branch**: `004-diarization` | **Date**: 2026-10-13 | **Spec**: [spec.md](spec.md)

**Input**: [Supplied design](../../docs/plans/diarization.md), formalized into the feature specification. Status: Phase 1 design complete; implementation has not started.

## Summary

Add an independent diarization CLI. Sequential native Nemotron and direct Community-1 inference share decoded Canonical Audio; Domain performs supported gap filling and exact prepared-interval correction. Publish one final speaker timeline, with lifecycle skips and automatic secondary fallback. Public and native rules live in [contracts](#design-artifacts), rather than being restated here.

## Technical Context

**Language/Version**: Python 3.12 (`>=3.12,<3.13`), native ctypes C ABI.

**Primary Dependencies**: existing NumPy 2.4.2 and PyICU; installed `pyannote-ncnn-plda==0.1.0` pinned to `34c8982e243eda9e42834ed255067ab727410379`, SciPy 1.16.2, NCNN 1.0.20260526, SoundFile 0.13.1 and kaldi-native-fbank 1.22.3. Retain the existing uv NumPy override. NeMo source `083861c241061562b8ec29eb06d7f6cdc3af8775` and its installed shared C library. No new engine/environment installation.

**Storage**: existing local Segment Manifest/Canonical Audio; one atomically replaced JSON artifact. In-memory native handles, samples and predictions; no engine intermediate files.

**Testing**: pytest 9.0.2; controlled fakes/fixtures; ABI-layout checks; architecture dependency test; ruff 0.15.5 and mypy 1.19.1; optional/required real diarization checkpoints.

**Target Platform**: current local macOS ARM64 installation, NeMo ggml Metal/CPU and independent NCNN Vulkan. Other native library filenames can be selected for the existing platform support boundary, but this feature promises no new platform port.

**Project Type**: existing Python CLI/service with Infrastructure, Protocol, Domain, Service, Composition and Controller layers.

**Performance Goals**: one canonical decode, one Nemotron attempt, at most one Community-1 attempt per nonempty task. Keep one shared contiguous float32 recording; avoid JSON/RTTM conversion and duplicate decode. No latency/throughput target or inference deadline was requested.

**Constraints**: full-recording predictions; offline geometry preset via the streaming C ABI; native cleanup before publication; lazy imports on skipped branches; preinstalled assets; no reference-driven inference.

**Scale/Scope**: one recording per CLI task; duration and memory limited by installed runtimes/available host memory, without a project-specific duration cap. GUI sequences commands and prevents concurrent tasks on the same work directory.

**Clarification status**: technical design questions resolved by [research.md](research.md). Runtime checkpoints still need to run during implementation; design completion does not assert successful inference.

## Constitution Check

**Before Phase 0 — PASS**: the supplied scope is test-first, preserves existing contracts and requires only the established layers. Integration tests target first-party calls/mapping/lifecycle, not third-party model accuracy. No speculative provider framework or installation workflow is added.

**After Phase 1 — PASS**:

- Tests precede each behavior change; each task below includes its own implementation and verification.
- Every planned in-scope entity is assigned one layer. Infrastructure never imports Protocol/Domain. Composition injects native factories/signatures/converters and maps results, following the current FireRed callback pattern.
- Standard typed callables implement assembly seams; no Infrastructure interface is implemented in Composition. Runtime interfaces, where used, and their adapters stay together in Infrastructure.
- All tasks trace to FR-001–FR-012 and the contracts; independent file ownership enables safe parallel work. General agent/model/review policy is referenced, not copied.
- Atomic publication reuses the existing writer behind a failure-stage translation, preserving preparation behavior.

No constitution exception or amendment is required. Implementation must preserve these gates.

## Entities, layers and relationships

Detailed fields/invariants are in [data-model.md](data-model.md).

| Entity / function group | Layer | Relationship and responsibility |
|---|---|---|
| Speaker Activity, typed predictions, elementary intervals | Domain | Validated recording-local activity and pure timeline derivation |
| Agreement matrix, mapping evidence, fusion result | Domain | Consume predictions and a standard solver callable; derive accepted fills |
| Sample activity, conversion/mask/merge functions | Domain | Convert fused activity and apply manifest interval values |
| NeMo config/segment structures, signature metadata, pure factories/converters | Protocol | Describe C ABI values without loading/calling a library |
| Diarization document and codec | Protocol | Closed serialized artifact values; no Domain imports |
| Command/progress/warning/result/failure values and validators | Protocol | Public CLI wire contract |
| DecodedAudio, manifest-byte reader, canonical validator/decoder, publication wrapper | Infrastructure | Own sample memory and filesystem I/O; publication-stage translation |
| NemotronInterval, CommunityInterval and adapter failure values | Infrastructure | Immutable Python-owned runtime results, diagnostics and cancellation distinction |
| NeMo ctypes adapter and native binding helpers | Infrastructure | Load symbols, configure signatures, call C functions, own handles/buffers |
| Community-1 adapter and local external-object boundary types | Infrastructure | Lazy library access, count/GPU parameters, stage objects and Vulkan ownership |
| Runtime prerequisite checks | Infrastructure | Inspect fixed assets/importability only on required branches |
| DiarizeAudio and workflow failure/progress helpers | Service | Orchestrate inputs, branch selection, pure transformations, cleanup and publication |
| Application builder and mapping/assembly callbacks | Composition | Supply Protocol factories/signatures to Infrastructure; map both results to Domain and final Domain values to Protocol document |
| CLI main/parser/output renderer | Controller | Parse, call assembled workflow, render Protocol messages; no Infrastructure imports |

The native adapter is generic over injected config/array types. Its typed factory/decoder callables and supplied signature metadata do not require a source-level Protocol reference. ctypes dynamic values remain inside that adapter; no raw native/library objects escape to Service or Domain. Protocol converters return boundary values/primitives only; Composition constructs the Infrastructure provider result values.

Composition builds a lazy SciPy solver callable. The secondary capability check verifies solver availability only when secondary inference is attempted, preserving skip behavior and classifying unavailable secondary dependencies as recoverable. Solver execution/fusion logic errors remain fatal.

## Assumptions and non-goals

Assume existing canonical/manifest invariants, same origin/channel, recording-local identities, preinstalled locked runtimes/assets, available host memory, and GUI work-directory sequencing. Current native ABI declarations match the pinned installed header; a changed ABI requires explicit compatibility verification.

Exclusions are FR-012 and the supplied design's non-goals: no transcription or GUI implementation, asset/runtime setup, extra segmentation tolerance, inference references, provider CLI intermediates, cross-recording identities, secondary CPU retry, concurrent engine execution or command-level directory lock. No AGENTS.md or sibling-repository edits.

## Test plan and verification

1. Write pure algorithm tests -> verify: duplicate-label counters, overlaps, clipped/empty inputs, rectangular/zero-evidence assignments, threshold boundaries, row denominator/maximum (including the documented near-tie tolerance), rejected-pair handling and gap-fill examples obey Fusion.
2. Write final-interval/artifact tests -> verify: ties-to-even, collapsed intervals, union/touching/split masks, identity preservation, overlap, sorted merging and closed canonical JSON obey Artifact/Fusion.
3. Write C/library boundary tests -> verify: native alignment/signatures/size prefixes, offline preset context sentinel, output-handle initialization, status/error copy, audio pointer/object identity, GPU/count arguments, partial initialization and cleanup obey Native/Lifecycle.
4. Write input/publication tests -> verify: canonical WAV properties/count/byte completeness, valid zero audio, resolved containment and canonical-file symlink rejection, one decoded array, reruns and write failures preserve inputs/prior complete output.
5. Write workflow/CLI tests -> verify: empty masks and zero/one observed speaker skip dependencies, multi-speaker paths fuse, secondary failures warn/fallback, valid empty/fewer-identity results are normal, fatal/cancelled paths preserve bytes, cleanup error stages match resource owners, and argument parsing precedes inference.
6. Run controlled suite/ruff/mypy/architecture -> verify: [quickstart commands](quickstart.md#controlled-verification) pass with real markers excluded and no preparation/ASR regression.
7. Run required native checkpoint with supplied assets -> verify: first-party ctypes/library invocation, selected runtime settings and two-engine mapping work on actual hardware. Skip/fallback outcomes cannot satisfy the required two-engine scenario. Missing assets or inaccessible hardware leave the checkpoint incomplete.

Tests verify first-party behavior, not third-party prediction accuracy. The research reference file and reported DER are not exact-output oracles.
