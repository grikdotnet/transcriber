# Preserve Nemotron activity and fill supported gaps with pyannote

Use the documented Nemotron / pyannote gap-fill algorithm: Nemotron supplies the base identities and active speaker sets, while pyannote contributes only single-speaker activity in empty Nemotron regions through accepted one-to-one identity mappings. The user selected this asymmetric fusion based on research into complementary engine weaknesses. Identity evidence uses the documented minimum agreement and support rules; fusion deliberately cannot replace active Nemotron identities, introduce identities absent from Nemotron, or fill pyannote overlaps. See [the algorithm](../prediction-fusion-algorithm.md).

The secondary engine is the user's NCNN Community-1 / PLDA / VBx implementation at `/opt/workspaces/pyannote-community1-plda-vbx`, using transcriber's NumPy version. Match and fuse full-recording predictions before applying the exact Speech Segment mask. Publish only the final masked activity; intermediary predictions and matching evidence are not published. Secondary-engine failure automatically produces masked Nemotron-only activity with a warning; Nemotron failure, cancellation, fusion failure, and publication failure do not trigger fallback.

The minimum single/single agreement is 3 seconds rather than the research algorithm's original 10 seconds, to admit supported mappings in short recordings. Use 70% minimum support rather than the original 80%, retaining strongest-candidate selection and one-to-one assignment. Reported research accuracy at the original thresholds does not establish accuracy at the adapted thresholds.

Community-1 is called directly as a Python library with Vulkan acceleration in transcriber's environment. Engines/assets are preinstalled prerequisites; no setup or GUI changes belong to this task. Inference has no fixed deadline, and the GUI coordinates commands for each work directory. Native in-process calls may defer cooperative cancellation until those calls return.

NeMo is called through a Python `ctypes` adapter around its supported C ABI, using the `v3-offline` preset with the streaming API. This allows the engines to share decoded samples, preserves native segment precision, and gives the application ownership of model/stream cleanup. NeMo and Community-1 GPU indices are independently configurable because the runtimes enumerate devices separately. Community-1 receives Nemotron's observed speaker count as both the minimum and maximum bound; this is a hard count request capped by usable observations, rather than a soft hint.
